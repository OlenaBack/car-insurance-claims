## 7. Observations and risks

1. **Enum labels are now trusted from the source, not from keywords.** Nulling only string fields removes the false 'missing' cases of the previous run, but it also means some kept enum labels (especially `fault`, `severity`, `time_of_day`) may not be inferable from the story at all. QCAR text is LLM-written from the row, so many are, but the hand-verified golden set must still check each one.
2. **Keyword contradiction flags are crude** (e.g. 'rain' in 'no rain'); they only trigger `needs_review`, never nulling.
3. **Label-first circularity:** the 12 label_first texts were generated by Claude to fit labels Claude defined, so they are clean, internally consistent and probably easier than real claims. If an evaluated model is from a similar family it may do better on them; evaluated models (Gemini, Qwen) differ, but report label_first and QCAR/Cleanlab accuracy separately.
4. **Cleanlab docs lack most schema labels** (only make/year mapped, the first policy vehicle may not be the one in the accident). They are still null + needs_review and need hand labelling.
5. **Noise is our own transformation** and mixed-language insertions are generic statements that may contradict facts; the evidence heuristics only match English. Source text contains literal '�' / '?' encoding artefacts, left untouched.
